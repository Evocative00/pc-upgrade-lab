## 적용 전 확인

비회원은 직접 입력·자동 인식·부품 선택·호환 검사를 이용하고 계정에 저장할 때 로그인한다. 이 정책과 기존 `user_id=NULL` PC를 보존하고 회원 목록에서 숨기는 정책은 이미 확정되어 있다.

V11이 아직 적용되지 않은 개인 DB에서 다음을 조회한다.

```sql
SELECT version, success FROM flyway_schema_history WHERE version = '11';
SELECT COUNT(*) AS assigned_pc_count FROM pc_configuration WHERE user_id IS NOT NULL;
```

- V11 결과가 없고 개수가 0이면 숫자 개발 소유자 충돌 없이 적용할 수 있다.
- V11 결과가 없고 개수가 1 이상이면 해당 개발 PC의 소유자를 먼저 확인한다. 자동으로 삭제·첫 회원 귀속·NULL 변경하지 않는다.
- V11이 이미 성공한 DB의 숫자 회원 ID는 정상 회원 데이터일 수 있다. 임의로 수정하지 않는다.
- 기존 V11 적용이 이미 실패한 DB는 생성된 테이블과 Flyway 실패 기록을 별도로 확인한다. 이 수정은 과거의 실패 상태를 자동 복구하지 않는다.

남은 사용자 환경 확인: 개인 MySQL(8.4 등)의 실제 상태, 개인 Google 설정을 이용한 비회원 최신 초안→실제 로그인→복구→저장 왕복, Windows PowerShell 검증 스크립트 실제 실행. PR 작성자가 보고한 기존 Google 수동 확인과 이번 모의 인증 검사를 구분한다.

구성 화면의 호환성 API 연결은 아직 후속 작업이다. 화면은 계속 ‘호환성 미검사 · 확인 필요’를 표시하며 전체 PC 호환성을 보장하지 않는다. 카카오 로그인도 이번 변경에 포함되지 않는다.

## 업로드 및 머지 방법

현재 GitHub 연결은 Git 데이터 쓰기를 403으로 거절했다. 원본 PR과 원격 dev는 변경하지 않았고 새 PR도 생성되지 않았다.

적용 패키지의 bundle을 새 로컬 브랜치로 가져와 검토한 뒤 사용자 계정에서 푸시한다. PR은 `fix/pr25-pr27-integration` → `dev`로 만든다. 두 원본 PR을 개별 머지하는 대신 통합 수정 PR을 **Create a merge commit** 방식으로 머지하면 원본 커밋의 연결을 유지할 수 있다. Squash/rebase를 선택하면 원본 PR의 머지 상태와 이력 보존 방식이 달라질 수 있다.
