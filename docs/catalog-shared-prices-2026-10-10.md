# 첫 14종 중앙 가격 공유 실행 안내

2026-10-10. [구현안](catalog-shared-prices-plan-2026-10-10.md)의 사용자 승인 범위대로 첫 14종의 공통 ID 조회·로컬 연결·신선도·장애 표시를 구현했다. 이 최초 v1 구현 문서의 제공 자료는 승인된 **상품 14종·가격 8종**의 고정 스냅샷이다. 현재 운영 v2는 **307종·가격 80종·미확인 227종**이며 제품 식별 버전과 가격 버전을 분리했다. [현재 전체 중앙 가격 안내](catalog-all-shared-prices-2026-10-10.md)를 따른다. 이후 승인된 Cloudflare Workers Free 중앙 제공기를 배포했고 실제 Java HTTPS 조회를 검증했다. 두 실제 기기의 화면 검수는 남아 있다.

이 문서의 독립 Java 제공기는 기존 loopback 검수 방식이다. [Worker 제공기와 팀 토큰](catalog-worker-prices-2026-10-10.md)은 동일 계약을 **https://pc-upgrade-shared-prices.joony1024.workers.dev**에서 제공하고, HTTPS 중앙 연결에는 backend의 `CATALOG_SHARED_PRICES_API_TOKEN`이 필수다. 운영 실행 설정과 배포 결과는 Worker 안내를 따른다.

## 동작과 적용 범위

독립 제공 서버는 `GET /api/v1/prices?canonicalIds=공통UUID,...`로 요청한 상품만 반환한다. [승인 미리보기](../data/catalog-review/pilot-import-preview-2026-10-10.json)·[가격 파일](../data/catalog-review/pilot-approved-prices-2026-10-10.json)의 고정 해시와 기존 승인·근거 검사를 통과해야 실행된다. 원래 상품 구성·판매 단위·가격 출처·관측시각을 유지하고 상품은 비활성·미검증 상태로 제공한다. 파일 변경을 새 가격으로 자동 수용하지 않는다.

자료 버전은 `pilot-2026-10-10-28cc2bacb534dcc2-3028116ce4cae9ad`다. 승인된 8종 외 6종은 `NO_PRICE`로 구분한다. 요청이 유효한 공통 UUID지만 제공 범위에 없으면 `UNKNOWN_PRODUCT`, 잘못된 UUID·중복·추가 파라미터는 HTTP 400이다. 공통 UUID 1~100개만 허용하고 다른 경로와 쓰기 요청은 제공하지 않는다.

이번 단계는 승인된 고정 관측과 정확히 일치하는 응답만 허용한다. 제공 서버의 가격 파일만 바꾸면 검증을 거부하므로 새 가격 승인 시 스냅샷·버전·클라이언트 검증 기준도 함께 갱신해야 한다. 정기 수집 단계에서는 상품 식별 검증을 유지하면서 승인된 새 관측 버전을 클라이언트 코드 갱신 없이 받아들이는 정책을 별도로 확장해야 한다.

로컬 backend는 명시적으로 중앙 조회를 켰을 때만 공통 ID로 요청한다. 로컬 상품 UUID·회원·PC 정보·수집 원문은 보내지 않는다. 응답의 버전·요청 ID 집합·상품 구성·RAM 장수·승인 금액/출처/관측시각·신선도 정책을 대조한다. 중앙 범위의 14종에서 연결 오류나 자료 불일치가 발생하면 `UNAVAILABLE`이며 로컬 DB 가격으로 대체하지 않는다. 나머지 상품은 `LOCAL / NOT_IN_SCOPE`로 기존 로컬 가격을 사용한다.

| 중앙 조회 결과 | 화면·상품가 합계 |
| --- | --- |
| 관측 후 48시간 미만 | 최근 관측, 합계에 포함 |
| 48시간 이상·7일 미만 | 오래된 관측 경고, 합계에 포함 |
| 7일 이상 | 과거 관측과 만료 표시, 합계에서 제외 |
| 승인 상품의 가격 없음 | 현재 상품가 미확인, 합계에서 제외 |
| 중앙 미등록 | 카탈로그 미등록, 합계에서 제외 |
| 중앙 연결 실패 | 연결 실패 표시, 마지막 정상 관측이 있으면 참고용으로 유지하되 합계에서 제외 |

경계는 `age >= threshold`다. 기준은 backend의 UTC 시계이며 프론트가 별도 판정하지 않는다. 성공 조회 때 원 관측시각을 유지하고 조회 시도·마지막 성공시각을 별도 필드로 제공하며, 장애 화면에는 캐시의 마지막 성공 조회를 표시한다. 캐시는 프로세스 메모리의 대상 14종으로 제한하며 backend 재시작 시 사라진다. RAM 2개 키트는 장착 수량 2개에 한 세트 가격을 적용하고, 모델만 확인한 PC 부품은 상품가를 연결하지 않는다.

## 기존 backend 실행 구성

**기존 실행 구성은 바꿀 필요가 없다.** 중앙 조회 기본값은 꺼짐이며 기존 `SPRING_PROFILES_ACTIVE=local`, JDK 21·MySQL·`DB_PASSWORD`·OAuth 설정을 유지한다. 이번 변경으로 새 Flyway 파일이나 DB 적재를 추가하지 않았다. 일반 backend 시작·pull·화면 새로고침이 판매처에서 가격을 수집하지 않는다.

중앙 조회를 로컬에서 직접 검수할 때만 아래 별도 서버와 선택 설정을 사용한다. 개인 설정 파일은 덮어쓰거나 저장소에 추가하지 않는다.

### 1. DB 없는 자료 검사

프로젝트 루트 PowerShell에서 JDK 21 환경으로 실행한다. DB·비밀번호·OAuth·웹 서버를 사용하지 않는다.

```powershell
.\backend\gradlew.bat --project-dir .\backend verifySharedCatalog
```

정상 결과는 `products=14 prices=8 databaseAccess=0`과 위 자료 버전이다.

### 2. 독립 제공 서버 시작

별도 터미널 또는 Gradle 실행 구성에서 다음 작업을 시작한다.

```powershell
.\backend\gradlew.bat --project-dir .\backend sharedCatalogPrices
```

기본 주소는 `http://127.0.0.1:8081`이다. DB·개인 properties·Spring·Flyway·OAuth를 시작하지 않는다. 종료는 터미널의 Ctrl+C를 사용한다. 다른 포트가 필요하면 `sharedCatalogPrices --args="--port 8082"`로 실행한다. 현재 프로토타입은 loopback에만 바인딩하므로 다른 기기에서 이 주소에 연결할 수 없다.

### 3. 평소 backend에 선택 설정 추가

중앙 조회를 검수할 **backend 실행 구성의 환경변수**에 두 항목을 추가한다.

```text
CATALOG_SHARED_PRICES_ENABLED=true
CATALOG_SHARED_PRICES_BASE_URL=http://127.0.0.1:8081
```

IntelliJ에서는 기존 `backend [bootRun]` 환경변수에 추가하고 기존 DB·OAuth 값은 유지한다. 개인 `application-local.properties`를 사용하는 경우 아래 두 속성으로 동일하게 설정할 수도 있다. `.env`만 만들어서는 적용되지 않는다.

```properties
catalog.shared-prices.enabled=true
catalog.shared-prices.base-url=http://127.0.0.1:8081
```

backend를 재시작한 뒤 기존 frontend를 그대로 사용한다. 이 안내의 재시작은 일반 `bootRun`의 기존 Flyway 동작을 포함하므로 DB가 준비된 본인 환경에서 수행한다. 이번 구현 검증에서는 실제 MySQL·일반 `bootRun`을 실행하지 않았다. 중앙 조회를 끄려면 enabled를 false로 바꾸고 backend를 재시작한다. 중앙 제공 서버만 끄면 14종은 연결 실패로 표시된다.

프론트 실행 구성·Vite 프록시의 새 설정은 필요 없다. 평소 `/api/catalog/products`를 통해 로컬 backend를 조회한다. 중앙 주소는 HTTPS 또는 IP 주소로 명시한 loopback HTTP만 허용하며 경로·사용자 정보·쿼리·fragment를 포함할 수 없다. 중앙 조회 제한은 기본 2초·응답 최대 64KiB이며 리다이렉트를 따르지 않는다.

## 직접 확인 순서

1. 중앙 조회를 끈 기본 실행에서 기존 검색·PC 연결·가격 표시를 확인한다.
2. 독립 제공 서버와 선택 중앙 설정으로 backend를 실행한다. 첫 14종 검색·상세에서 ‘중앙 가격’, 승인 가격 8종과 미확인 6종을 확인한다. 나머지는 ‘로컬 가격 · 중앙 대상 범위 밖’이다.
3. 가격 출처와 원 관측시각을 확인한다. 자료는 UTC 2026-10-09(한국 시간 10일)의 관측이므로 검수 날짜에 따라 오래된 관측 또는 만료가 표시되는 것이 정상이다. 장애 확인 때 마지막 성공 조회가 원 관측과 구분되어 표시된다.
4. Neo RAM 키트 장착 수량 2개가 한 세트 금액으로 합산되고 모델만 확인한 부품은 제외되는지 확인한다.
5. 가격이 있는 14종 대상 상품을 조회한 뒤 제공 서버를 종료하고 ‘가격 새로고침’을 누른다. 마지막 확인 가격·연결 실패·합계 제외를 확인한다. backend를 재시작해 캐시가 없으면 가격 없음과 별개의 연결 실패 안내가 나와야 한다.

## 검증과 남은 단계

2026-10-10 검증 결과:

- `verifySharedCatalog`: 승인 해시·근거 자료·상품 14종·가격 8종 검사 통과, DB·웹 서버 접근 없음.
- backend `test`: **76개 클래스·371개 테스트 통과**, 실패·오류·건너뜀 0. 그중 새 공유 검사 19개는 독립 HTTP 제공 7개, 어댑터·설정·오류·본문 크기/시간·동시 조회 11개, 독립 H2 두 DB 비교 1개다.
- 서로 다른 로컬 상품 UUID를 가진 H2 두 환경에서 같은 공통 ID의 CPU·RAM 목록/상세 가격·원 관측시각·자료 버전·동일 기준 신선도가 일치했다. 조회 전후 모든 PUBLIC 테이블의 행과 값이 일치했고, 중앙 관측을 로컬 가격 테이블에 삽입하지 않았다.
- 프론트 전체 **134개 테스트 통과**, `npm.cmd run lint`·`npm.cmd run build` 통과. 계약 검증·화면 렌더·RAM 키트 합계·모델만 확인·만료·장애 캐시 제외를 포함한다.
- 독립 코드 검토에서 네트워크를 포함한 어댑터 전역 잠금을 발견해 제거했다. 6개 동시 시간 초과 검사가 통과했고 캐시 갱신만 짧게 보호한다. 변경 범위의 whitespace 검사도 통과했다.

자동 검증은 독립 H2 환경·loopback HTTP·프론트 계약/화면 렌더 검사이며 실제 MySQL·Google 로그인·Windows 수집기·실제 브라우저 수동 검수·두 실제 기기의 중앙 동기화 검증과 구분한다. 제공 서버는 테스트 안에서만 실행·종료했으며 평소 backend와 개인 설정은 변경하지 않았다.

**가격 자동 수집·갱신은 아직 없다.** 새로고침은 제공 서버의 승인 스냅샷을 다시 조회한다. 이후 [Worker 안내](catalog-worker-prices-2026-10-10.md)의 승인된 Workers Free 배포·실제 HTTPS 검증을 완료했다. 다음 검수는 데스크톱·노트북의 각 backend에 같은 운영 URL·팀 토큰을 설정한 뒤 동일 버전 조회를 확인하는 것이다. 정기 수집의 주기·판매처·이상값 검토·새 자료 승인 정책은 따로 정한다. 실제 MySQL 변경·정기 수집은 이 공유 기능 단계에서 하지 않았다.
