# 1주차 PC 화면·API 통합 기록

검토 기준: 2026-09-28, dev `47162e489c80cd35a69f5d725a3e1d20d281da61` + PR #10 `a05c515aa86ff9d7818256c15eb33833d0013b0d`.

## 변경 이유와 결과

PR #10의 화면은 브라우저 localStorage에 저장하는 단계였다. PC API가 PR #12로 dev에 병합되어, 화면의 등록·목록·상세·수정을 실제 서버에 연결한다.

- `pcRepository.ts`: POST/GET/PUT `/api/pcs`를 사용한다. Vite 개발 서버의 기존 `/api` 프록시가 8080 백엔드로 전달한다.
- 저장에 실패하면 입력을 유지하고 서버 오류를 알린다. 연결 실패·시간 초과를 구분하며 자동 재전송 또는 localStorage 대체 저장을 하지 않는다. 응답을 받지 못한 저장은 서버에 반영됐을 수 있어 목록 확인을 안내한다.
- 상세 조회의 `404 PC_NOT_FOUND`만 'PC 없음'으로 처리한다. 수정 실패나 프록시의 404는 오류다.
- 저장 중 입력·취소·수집기 실행 링크를 잠그고 중복 제출을 막는다. 저장 도중 다른 페이지로 이동하면 이전 응답이 현재 페이지를 강제로 바꾸지 않는다.
- 저장된 AUTO 부품에는 화면에서만 쓰는 `persisted` 표시를 붙여 재인식 전 확인한다. `edited`와 별개여서 과거 편집 여부를 임의로 단정하지 않는다.
- 목록은 20개씩 이전·다음 페이지를 제공한다. 오류 또는 빈 페이지에서도 이전으로 돌아갈 수 있다.
- 용량 입력 문자열을 보존하고, 변환 후 0·음수·비유한 용량을 저장 전에 차단한다. 비워 둔 용량은 null이다.
- 예시 제품 선택은 이름만 입력하고 `UNMATCHED`·제품 ID null을 유지한다. 실제 카탈로그 API 연결은 후속 작업이다.

API의 필드명·부품 코드·응답 구조와 백엔드·DB 스키마는 변경하지 않았다. 이전 localStorage 기록은 자동 이전하거나 삭제하지 않는다. 기존 브라우저 기록의 ID와 서버 PC ID는 서로 다른 저장소의 값이다.

아래는 Codex의 격리 환경에서 수행한 결과이며, 사용자 Windows·MySQL 검증 결과와 구분한다.

HTTP 검증은 현재 백엔드를 새로 컴파일하고 H2 파일 DB(MySQL 모드)로 실행했다. 프런트에서 사용하는 `createHttpPcRepository`를 그대로 호출했다. 등록 201, 조회·수정 200, 상세 없음/수정 없음 404 구분, 잘못된 입력 400, 오류 필드 전달, 실패한 수정의 데이터 보존을 확인했다.

RAM·저장장치 두 항목 보존과 반복 수정 시 누적 방지, PC 21개를 20개+1개로 조회, 최근 수정 정렬을 확인했다. 백엔드 프로세스를 종료하고 재시작한 뒤 저장된 상세와 21개 목록 유지도 확인했다. H2 MySQL 모드는 실제 MySQL 검증을 대신하지 않는다.

실제 브라우저 상호작용과 Windows 수집기 실행은 여기서 수행하지 않았다. 이 패치로 사용자 MySQL까지 연결되는 최종 확인은 아래에 따로 기록한다.

## Windows에서 확인할 항목

백엔드는 기존 MySQL `local` 프로필, 프런트는 `npm run dev`로 실행한다. `http://localhost:5173/#/pcs`에 접속한다. 이번 화면 검증에는 새 검증용 PC를 등록하고, 기존 검증용 PC는 그대로 둔다.

| ID | 확인 | 기대 결과 | 사용자 결과 |
| --- | --- | --- | --- |
| UI01 | 기존 서버 PC 목록·상세 조회 | MySQL에 저장했던 PC 표시. localStorage 기록과 혼동하지 않음 | 미검증 |

실제로 확인한 항목만 결과·일시·필요한 증거를 적는다. UI09의 서버 페이지 응답은 자동 검증에서 확인했지만, 실제 화면 버튼 조작은 별도 확인 대상이다. 검증용 데이터의 일괄 삭제 기능은 이번 범위에 없다.

## 실행 명령

Node 24 환경의 frontend 폴더에서 실행한다. 새 테스트는 Node 내장 테스트 기능을 사용하므로 추가 테스트 패키지는 없다.

```powershell
npm ci
npm test
npm run lint
npm run build
npm run dev
```

`npm run dev` 터미널은 화면을 쓰는 동안 켜 둔다. MySQL 비밀번호나 실제 스캔 토큰은 검증 기록·PR에 넣지 않는다.
