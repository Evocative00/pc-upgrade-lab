PC 업그레이드 CPU·GPU 점수 비교: 실행·판단 안내
==============================================

목적
  캡스톤 시연에서 현재 PC와 선택한 게임의 공식 최소·권장 사양을 비교한다.
  CPU·GPU 모델명이 달라도 공개 벤치마크로 한 번 더 비교한다. CPU는 Blender Open Data
  렌더링 점수, GPU는 Tom's Hardware 게임 실측 기반 상대값을 쓴다.
  이 결과는 예상 FPS, 공식 요구 사양 충족, 구매 보증이 아니다.

실행 방법 (Windows)
  1. 프로젝트의 README에 따라 MySQL과 백엔드 local 프로필을 준비한다.
     개인 DB 비밀번호는 환경변수 DB_PASSWORD로만 전달한다. 채팅이나 Git에 올리지 않는다.
  2. 프로젝트 루트에서 backend\gradlew.bat --project-dir backend bootRun 을 실행한다.
     정상 실행되면 백엔드는 보통 http://127.0.0.1:8080 에 열린다.
  3. 별도 PowerShell에서 frontend 폴더로 이동해 npm.cmd install (처음 한 번),
     npm.cmd run dev 를 실행한다. 표시된 로컬 주소(보통 http://127.0.0.1:5173)를 연다.
  4. 로그인 후 왼쪽 '업그레이드 플랜'에서 저장된 PC를 고르거나 PC 정보를 입력한다.
     게임과 목표를 선택하고 '진단 결과 보기'를 누른다.
  5. 공식 최소·권장 사양 카드 아래 'CPU·GPU 모델 비교'를 확인한다.
     CPU·GPU 모두 최소·권장 기준 모델 대비 배율(예: 기준의 0.65배)로 보여준다.
     점수의 절대값은 자료마다 단위가 달라 화면에 보여주지 않는다.
     '추천 플랜'은 현재 한 가지 점검 우선순위만 보여준다.

알고리즘 (CPU Blender 점수 + GPU 게임 성능 상대값)
  1. 공식 게임 요구 사양은 기존 자료 그대로 사용한다. RAM·VRAM은 입력된 용량으로,
     CPU·GPU의 공식 사양 비교는 동일 모델 여부로 판단한다.
  2. CPU는 Blender Open Data(CC0)의 CPU 렌더링 점수로 비교한다. 표 위치:
     frontend/src/features/planner/cpuBlenderScores.ts (자동 생성 파일, 직접 수정 금지)
     - 점수 = 장면 monster·junkshop·classroom의 분당 샘플 수 중앙값 합, Blender 4.5 기준.
     - 3.0~5.2 버전 측정값은 버전별 보정 계수(0.91~1.05)로 4.5 기준으로 환산한다.
       환산 오차는 대략 ±10%이므로 기준 대비 0.9~1.1배는 사실상 비슷한 수준으로 본다.
     - 단일 소켓 측정만 쓰고, 장면마다 3회 이상 측정된 CPU만 넣는다.
     - 멀티코어 렌더링 점수라서 코어 수가 많은 CPU가 게임 체감보다 높게 나올 수 있다.
  3. GPU는 칩셋별 게임 성능 상대값(GeForce GTX 1060 6GB = 100)으로 비교한다. 표 위치:
     frontend/src/features/planner/gpuRelativeScores.ts (자동 생성 파일, 직접 수정 금지)
     원본 자료: data/benchmark/gpu-relative-performance-2026-10-11.json (칩셋별 값·출처·신뢰도)
     - Blender GPU 점수는 RTX 레이트레이싱 하드웨어와 제조사별 렌더 방식 차이로
       게임 성능과 크게 어긋나서(예: RTX 2060 SUPER가 GTX 1060의 6배) 쓰지 않는다.
     - Tom's Hardware GPU 계층표의 1080p Ultra 래스터 결과를 우선 사용한다(2026표 46종,
       2022~2024표 32종). 2026표에는 GTX 1060이 없어 두 표에 모두 있는 14종으로 연결했다
       (환산 계수 1.18, 편차 약 4%).
     - Tom's 표에 없는 아주 오래된 카드·내장 그래픽 12종은 PassMark G3D Mark를 같은 눈금으로
       환산했다(공통 17종 기준, 편차 약 15%). 이 항목은 신뢰도 '낮음'이다.
     - Windows는 GPU 이름에 VRAM 용량을 붙이지 않으므로 같은 칩셋의 VRAM 변형
       (예: RTX 3060 12GB·8GB)은 낮은 값을 쓴다. VRAM 용량은 공식 사양 카드에서 따로 비교한다.
     - 공식 사양의 약식 표기 'GeForce 560'은 GTX 560 값으로 찾는다.
  4. 최소·권장 단계마다 공식 예시가 여러 정확 모델이면 점수가 가장 낮은
     예시를 해당 단계의 기준으로 삼는다. 현재 부품이 기준 이상이면 '기준 이상',
     낮으면 '기준보다 낮음'이다. 예시가 계열명뿐이거나 현재/예시 모델이 표에 없으면 '판단 보류'다.
  5. 선택한 게임들에서 확인된 RAM·VRAM 용량 부족을 우선한다. 그다음 CPU·GPU 배율이
     낮은 부품을 살핀다. 같은 단계에서는 해당 게임 수, 그다음 부족 정도를 비교한다.
     부족 정도는 CPU·GPU 모두 1 - (내 점수 ÷ 기준 점수)다.
     이 결과는 구매 제품 추천이 아니라 '가장 먼저 점검할 부품' 하나다.
  6. 정보가 부족하면 부족·호환이라고 단정하지 않는다.

점수표 다시 만들기 (frontend 폴더, Node 24)
  1. https://opendata.blender.org/snapshots/opendata-latest.zip 을 받아 압축을 푼다(약 1.9GB).
     원본은 저장소에 넣지 않는다.
  2. node scripts/build-cpu-blender-scores.mjs <opendata-*.jsonl 경로> <스냅샷 날짜 YYYY-MM-DD>
  3. GPU: data/benchmark/의 JSON을 검토·수정한 뒤
     node scripts/build-gpu-relative-scores.mjs ../data/benchmark/gpu-relative-performance-YYYY-MM-DD.json
  4. npm.cmd test 로 점수표 검사(모델 중복·표본 수)와 비교 테스트를 확인한다.

현재 범위와 주의사항
  - 대상은 게임 5개(롤, 발로란트, 배틀그라운드, 오버워치 2, 사이버펑크 2077)다.
  - CPU·GPU 배율은 실제 FPS나 공식 요구 사양 충족을 뜻하지 않는다. 자료 오차가 있어
    0.9~1.1배는 비슷한 수준으로 본다.
  - Blender 자료에 없는 아주 오래된 CPU(A6-3650, Phenom X3 8650 등)는 '판단 보류'다.
  - 롤 권장 CPU는 Riot 공식 표기대로 'Core i5-8250'이다. 실제 제품은 노트북용 i5-8250U뿐이라
    점수표와 연결되지 않으며, 팀이 표기 해석을 정하기 전까지 '판단 보류'다.
  - 선택한 해상도·목표 FPS와 예산은 기록만 하며 점수·추천 계산에 반영하지 않는다.
  - 특정 교체 제품, 비용, 교체 후 호환성은 아직 자동 확정하지 않는다.
  - GPU 값을 바꿀 때는 JSON을 팀원이 검토하고 출처·확인일을 함께 고친 뒤 다시 생성한다.
    같은 모델의 세부 변형(VRAM 등)은 별도 제원으로도 확인한다.
  - 데스크톱 업그레이드 전용이다. GPU 표에는 데스크톱 GPU만 넣는다(노트북 GPU는 판단 보류).

개발 확인 명령 (frontend 폴더)
  npm.cmd test
  npm.cmd run lint
  npm.cmd run build
