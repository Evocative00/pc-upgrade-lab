PC 업그레이드 시연용 내부 점수: 실행·판단 안내
=============================================

목적
  캡스톤 시연에서 현재 PC와 선택한 게임의 공식 최소·권장 사양을 비교한다.
  CPU·GPU 모델명이 달라도 팀이 직접 정한 상대 등급(1~8)으로 한 번 더 비교한다.
  이 등급은 실측 벤치마크, 성능 향상률, 예상 FPS, 구매 보증이 아니다.

실행 방법 (Windows)
  1. 프로젝트의 README에 따라 MySQL과 백엔드 local 프로필을 준비한다.
     개인 DB 비밀번호는 환경변수 DB_PASSWORD로만 전달한다. 채팅이나 Git에 올리지 않는다.
  2. 프로젝트 루트에서 backend\gradlew.bat --project-dir backend bootRun 을 실행한다.
     정상 실행되면 백엔드는 보통 http://127.0.0.1:8080 에 열린다.
  3. 별도 PowerShell에서 frontend 폴더로 이동해 npm.cmd install (처음 한 번),
     npm.cmd run dev 를 실행한다. 표시된 로컬 주소(보통 http://127.0.0.1:5173)를 연다.
  4. 로그인 후 왼쪽 '업그레이드 플랜'에서 저장된 PC를 고르거나 PC 정보를 입력한다.
     게임과 목표를 선택하고 '진단 결과 보기'를 누른다.
  5. 공식 최소·권장 사양 카드 아래 'CPU·GPU 모델 비교'를 확인한다.
     각 부품의 최소 기준과 권장 기준을 따로 보여준다.
     '추천 플랜'은 현재 한 가지 점검 우선순위만 보여준다.

알고리즘 (prototype-v1)
  1. 공식 게임 요구 사양은 기존 자료 그대로 사용한다. RAM·VRAM은 입력된 용량으로,
     CPU·GPU의 공식 사양 비교는 동일 모델 여부로 판단한다.
  2. 별도의 내부 등급표에서 CPU와 GPU를 각각 1~8등급으로 찾는다.
     CPU 등급과 GPU 등급은 서로 비교하지 않는다. 표 위치:
     frontend/src/features/planner/internalScores.ts
  3. 최소·권장 단계마다 공식 예시가 여러 정확 모델이면 내부 등급이 가장 낮은
     예시를 해당 단계의 기준으로 삼는다.
     현재 부품 등급이 기준 이상이면 '내부 기준 이상', 낮으면 '내부 기준보다 낮음'이다.
     예시가 계열명뿐이거나 현재/예시 모델이 표에 없으면 '판단 보류'다.
  4. 선택한 게임들에서 확인된 RAM·VRAM 용량 부족을 우선한다. 그다음 내부 등급이
     낮은 CPU·GPU를 살핀다. 같은 단계에서는 해당 게임 수와 등급 차이를 비교한다.
     이 결과는 구매 제품 추천이 아니라 '가장 먼저 점검할 부품' 하나다.
  5. 정보가 부족하면 부족·호환이라고 단정하지 않는다. 모델을 정확히 입력하거나
     팀이 등급표를 검토·확장한 후 다시 비교한다.

현재 범위와 주의사항
  - 대상은 게임 5개(롤, 발로란트, 배틀그라운드, 오버워치 2, 사이버펑크 2077)다.
  - 내부 등급은 팀의 시연용 가정이다. 실제 성능·FPS 또는 공식 요구 사양 충족을 뜻하지 않는다.
  - 선택한 해상도·목표 FPS와 예산은 기록만 하며 점수·추천 계산에 반영하지 않는다.
  - 특정 교체 제품, 비용, 교체 후 호환성은 아직 자동 확정하지 않는다.
  - 새 모델을 추가하거나 등급을 바꿀 때는 팀원 검토 후 버전을 올리고 테스트한다.
    같은 모델의 세부 변형(VRAM 등)은 별도 제원으로도 확인한다.

개발 확인 명령 (frontend 폴더)
  node --test tests/internalScores.test.ts tests/prototypeRecommendation.test.ts
  npm.cmd run lint
  npm.cmd run build
