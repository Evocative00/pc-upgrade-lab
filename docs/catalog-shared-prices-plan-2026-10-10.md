# 첫 14종 중앙 가격 공유 구현안

2026-10-10, 사용자가 첫 14종 검색·PC 연결과 UI 개선의 직접 검수에서 문제가 없다고 확인했다. 다음 구현은 이 14종의 공통 ID로 같은 승인 상품가와 관측시각을 여러 로컬 환경에 전달하는 경로를 검증한다. [전체 설계](catalog-db-expansion-design-2026-10-09.md)의 중앙 공유 연결 단계이며, 후속 제품 확대에 재사용할 기반이다.

사용자가 **‘이 범위로 구현 승인 (추천)’**으로 승인했다. 승인 범위의 API·로컬 연결·화면 표시를 구현했고, 실행·검증은 [중앙 가격 공유 실행 안내](catalog-shared-prices-2026-10-10.md)에 기록한다. 실제 중앙 배포는 위치·비용·운영 계정을 확정한 뒤 별도 승인받는다.

## 사용할 자료

- 상품 14종·모델 13개·공통 ID는 [승인 미리보기](../data/catalog-review/pilot-import-preview-2026-10-10.json)와 [적용 승인 기록](../data/catalog-review/pilot-apply-approval-2026-10-10.json)을 기준으로 한다.
- 가격은 [승인한 8종 관측](../data/catalog-review/pilot-approved-prices-2026-10-10.json)의 금액·상품 구성·판매 단위·출처·원 관측시각을 유지한다. 나머지 6종은 가격 미확인이다.
- 기존 72종 준비 작업과 `importPilotCatalog`의 수동 적재 경로를 유지한다. 원자료·승인 해시는 수정하지 않는다.

## 구현 범위

| 작업 | 동작 |
| --- | --- |
| 승인 자료 제공 | 같은 자료 버전의 14종 공통 ID와 8종 관측을 읽기 전용으로 제공한다. 독립 제공 서버의 기본 준비에는 개인 DB·OAuth 설정을 요구하지 않는다. |
| 중앙 읽기 계약 | 공통 ID별 상품가·판매 단위·출처·관측시각·자료 버전·신선도를 반환한다. 요청 처리 시각을 가격 관측시각으로 바꾸지 않는다. |
| 로컬 연결 | 기존 로컬 상품 ID를 유지하고 공통 ID로 중앙 자료를 요청한다. 회원·PC·수집 원문을 중앙 서버로 보내지 않는다. |
| 단계적 사용 | 기본 실행은 기존 로컬 조회다. 중앙 조회는 명시적으로 설정한 경우에만 켠다. 첫 대상 14종과 나머지 로컬 상품을 구분해 표시한다. |
| 장애 표시 | 중앙 오류를 가격 없음·품절·0원으로 바꾸지 않는다. 마지막 정상 자료가 있으면 이전 관측과 연결 실패를 구분한다. 로컬 가격으로 조용히 대체해 두 기기의 결과가 달라지게 하지 않는다. |
| 화면·합계 | 자료 출처와 신선도를 표시하고 기존 RAM 판매 묶음 환산을 유지한다. 모델만 확인한 부품에는 상품가를 연결하지 않는다. |

중앙 응답의 공통 ID·부품 종류·정확 상품 구성·판매 단위를 로컬 자료와 대조한다. 등록되지 않은 ID, 중앙 자료 범위 밖의 상품, 승인 상품에 가격이 없는 경우, 연결 실패를 서로 다른 결과로 처리한다. 비활성·미검증 상태를 그대로 제공하며 구매 후보를 자동 활성화하지 않는다.

## 신선도 제안

[기존 설계](catalog-db-expansion-design-2026-10-09.md)의 제안값을 이번 구현 컨펌 범위에 포함한다. UTC 관측시각을 기준으로 48시간 미만은 정상, 48시간 이상·7일 미만은 오래된 관측 경고, 7일 이상은 과거 가격으로 표시하고 상품가 합계에서 제외한다. 경계는 `age >= threshold`로 계산하며 설정값과 주입 가능한 기준 시각으로 검증한다.

이 정책의 첫 적용 범위는 중앙 조회를 명시적으로 켠 14종이다. 기존 기본 로컬 조회와 전체 307종의 가격 표시 정책을 한꺼번에 전환하지 않는다. 조회 실패 시각과 관측시각을 분리하며, 자료가 오래됐다는 사실만으로 품절을 판정하지 않는다.

## 완료 기준

1. 같은 상품의 로컬 UUID가 다른 두 테스트 환경에서도 공통 ID로 조회한 금액·관측시각·판매 단위가 일치하며, 동일한 기준 시각에서 신선도가 일치한다.
2. 승인 14종 중 가격 8종·가격 미확인 6종을 정확히 구분하고, 자료 버전과 승인 해시 검증을 통과한다.
3. RAM 2모듈 키트는 장착 수량 2개일 때 한 세트 가격으로 합산하고, 모델만 확인은 상품가를 제외한다.
4. 잘못된 ID·상품 관계·응답, 중앙 중단·시간 초과, 48시간·7일 경계를 검증한다. 정상 요청을 반복해도 기존 상품·PC·가격 행을 변경하지 않는다.
5. 기존 로컬 모드의 검색·PC 연결·로그인·가격 흐름을 보존한다. backend H2와 프론트 변경 범위 검사·lint·build를 통과하고 선택적 중앙 실행 설정을 문서화한다.

두 테스트 환경은 로컬의 독립 데이터와 HTTP 검증 환경이다. 두 실제 기기의 동기화 완료는 중앙 배포 후 데스크톱·노트북에서 따로 확인한다.

## 이후 컨펌

이번 구현안 승인으로 실제 MySQL 변경·신규 판매 SKU 또는 가격 반영·중앙 배포·정기 수집·GitHub 업로드를 실행하지 않는다. 추가 스키마가 필요해지면 변경량을 먼저 제시한다. 기존 backend 실행 구성의 필수 설정은 유지하고 중앙 조회를 켤 때 필요한 추가 설정만 별도로 안내한다.

코드 검증 후 중앙 서버 위치·비용·운영 계정과 배포 범위를 제시해 승인받는다. 배포 후 두 실제 기기의 같은 가격 조회를 확인하고, 이어 정기 가격 수집 운영과 후속 카탈로그 확대를 진행한다.
