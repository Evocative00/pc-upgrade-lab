# PC 업그레이드 실험실 프론트엔드

React 19·TypeScript·Vite 기반 화면이다. 의존성·명령은 `package.json`과 `package-lock.json`, 전체 실행 환경은 [프로젝트 실행 안내](../docs/week1-setup.md)를 기준으로 한다.

## 뒤로가기와 임시 입력 복원

같은 탭에서 화면 이동·브라우저 뒤로가기·앞으로가기·새로고침을 해도 작성 상태를 이어 간다. `sessionStorage`를 사용하는 탭 단위 보관이며, 서버에 PC를 저장하는 기능과는 별개다. 새 의존성·환경변수·DB 마이그레이션은 필요 없다.

- PC 이름·부품별 입력·개수·개당 용량·카탈로그/모델 연결과 AUTO 보완 여부를 보관한다. 입력 중의 잘못된 값도 정상 값이나 미확인 `null`로 바꾸지 않고 복원한다.
- PC별 업그레이드 예산·목적·게임·프로그램·해상도·목표 프레임·작업 규모와 아직 추가하지 않은 게임 이름을 보관한다. 플랜 단계는 `#/pcs/new?step=3`, `#/pcs/17/edit?step=2`, `#/upgrade/pcs/17?step=4`처럼 주소에 기록해 브라우저 뒤로가기·앞으로가기도 직전 단계로 이동한다.
- 내 PC 목록·플랜의 저장 PC 목록 페이지 번호, 부품 검색창의 검색어·제품/모델 모드·마지막 검색 페이지·펼친 제품 ID를 보관한다. 검색창은 부품 행/자리별로 구분한다. 가격·검색 결과·PC 상세·호환성 응답은 복귀 시 다시 조회하며 임시 저장본을 최신 서버 정보로 표시하지 않는다.
- 일반 화면과 홈페이지 내부 스크롤 위치를 복원한다. 비동기 조회로 화면 높이가 늘어나는 동안 복원을 기다리고, 사용자가 직접 스크롤하면 대기를 중단한다.
- 승인한 동작: PC 저장 성공·초기화·삭제 시 해당 PC의 임시 구성·플랜·검색 상태를 비운다. 저장 중 다른 화면에서 새로 작성한 내용은 늦은 저장 응답이 지우지 않는다.
- 비회원에서 로그인하면 이어서 작성한다. 로그아웃·확인된 회원 변경 시 화면 임시 상태를 비우고 개인 화면을 다시 연다. 인증 서버 장애 시 기존 회원의 입력은 지우거나 표시하지 않고 재확인을 안내한다. 기존 로그인 왕복용 `draftBridge`의 보관 규칙과 로그인 후 자동 저장하지 않는 규칙은 유지한다.

자동 인식에서 **입력란에 반영된 부품**은 복원 대상이다. 검사 토큰·실행 링크·진행 중 네트워크 요청은 보관하지 않는다. 저장소가 차단되거나 꽉 차면 현재 앱 안의 화면 왕복은 메모리로 유지하지만 새로고침 후 복원은 보장하지 않는다.

구현은 `src/lib/pageState.ts`, `usePageState.ts`, `usePageScroll.ts`, `router.ts`와 각 기능의 입력 상태 연결에 있다. 검증은 `npm.cmd test`, `npm.cmd run lint`, `npm.cmd run build`를 사용한다. 실제 MySQL·소셜 로그인·Windows 수집기 통합 검증은 별도로 수행해야 한다.

## 로그인 화면

- Google·카카오·네이버의 공식 브랜드 자산과 색상을 사용하는 버튼, 반응형 소개 영역과 로그인 카드를 적용했다. 출처는 [브랜드 자산 안내](src/features/auth/assets/NOTICE.txt)에 기록했다.
- 서버의 제공자 목록에 따라 활성화된 로그인 버튼을 표시한다. 목록 조회에 실패하거나 목록이 비어 있으면 Google 버튼만 기본으로 표시한다. 실제 OAuth 사용에는 각 PC의 개인 설정과 제공자 콘솔 등록이 필요하다.
- 로그인 전 PC 초안 복구와 돌아갈 화면을 유지한다. 로그인 후 사용자가 저장 버튼을 눌러야 PC를 계정에 저장한다.
- 로그인 성공·실패 화면도 같은 스타일로 정리했다.

## 구성·플랜·내 PC 화면

PC 구성, PC 수정, 내 PC 목록·상세와 업그레이드 플랜은 같은 왼쪽 메뉴와 버튼·카드 스타일을 사용한다. PC 수정 화면에도 구성 그림·요약·호환성 안내를 표시하고, 부품 검색은 오른쪽 모달 패널에서 연다. 검색 패널은 Escape로 닫으면 검색 버튼으로 초점을 돌려준다.

구성 화면과 플랜의 열 수는 사이드바를 제외한 **본문 폭**을 기준으로 바뀐다. 구성 화면은 본문 1100px 이하에서 두 열, 760px 이하에서 한 열로 표시한다. 플랜은 본문 800px 이하에서 한 열로 표시한다. 모바일의 저장 버튼 줄은 공간이 부족하면 다음 줄로 내려가고, PC 목록 카드와 선택 표시도 화면 안에 들어오게 한다.

## PC 조립 스크롤 랜딩

첫 화면은 왼쪽 진행 문구와 오른쪽 PC 조립 장면을 하나로 묶었다. 화면을 고정한 채 조립 완료 100%까지 진행하고, 100~110%에서 전원 문구, 111~120%에서 캐치프레이즈와 PC 구성하기 버튼을 보여 준 뒤 VIRTUAL BUILD·DETAILS·푸터로 이어진다. 키보드로 구성 버튼에 접근하면 캐치프레이즈를 즉시 보여 주고 진행 문구는 숨겨 겹치지 않게 한다. 왼쪽 탭 바와 다른 기능 화면의 구조는 유지한다.

블랙·실버, 유리 케이스와 은은한 아이스 블루 LED를 사용한 자체 제작 3D 장면을 스크롤에 연결했다. 메인보드의 전원부·실드·소켓·슬롯과 CPU 쿨러의 방열핀·히트파이프·고정 장치를 보강했으며, GPU·RAM·CPU·SSD·케이블 등을 21개 독립 그룹으로 분해·조립한다.

- 240개 고유 이미지와 역순 재사용으로 480단계 왕복 동작을 제공한다. 이 홈페이지는 PC 사용을 기준으로 하며, 플레이어는 1600×1200 데스크톱 WebP만 사용한다. 기존 모바일 파일과 manifest 항목은 보존하지만 화면에서는 선택하지 않는다.
- 큰 스크롤 이동도 즉시 점프하지 않고 시간 기준으로 부드럽게 따라간다. 정확한 목표 이미지가 로딩 중이면 이동 방향에 맞는 준비된 포즈를 표시하며, 진행 중 요청은 완료한 뒤 최신 위치의 요청을 우선한다.
- 첫 소개 구간에서 전체 동작 범위를 덮는 기준 포즈를 최대 64개 준비한다. 기준 포즈와 근처 포즈 모두 같은 데스크톱 원본에서 실제 이미지 표시 영역의 픽셀 수(DPR 최대 2배, 원본 크기 상한)에 맞춰 동일한 해상도로 디코딩한다. 640×480 미리보기를 확대하거나 고해상도와 번갈아 표시하는 경로를 제거했다. 크기 조절은 [createImageBitmap 옵션](https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap)을 사용하며 추가 렌더는 필요 없다.
- 근처 포즈는 최대 8개, 기준 포즈는 해상도에 따라 최대 64개로 제한해 저장된 bitmap 픽셀 합계를 320MiB 이내로 유지한다. 예를 들어 1088×816에서는 기준 64개+근처 8개 약 243.8MiB, 원본 1600×1200에서는 기준 35개+근처 8개 약 315MiB다. 같은 포즈는 한 풀에서만 디코딩한다. 이 수치는 canvas·GPU·진행 중 디코더의 추가 메모리를 포함하지 않는다. 화면 크기·DPR 변경 시 필요한 해상도를 갱신하고, 화면 밖이나 비활성 탭에서는 요청·재시도 타이머·캐시를 정리한다.
- 모션 감소 설정에서는 완성된 정지 장면과 캐치프레이즈를 바로 보여 준다. 사용자가 해당 페이지에서만 애니메이션 표시를 선택할 수 있다.
- 640px 이하에서는 조립 장면을 마운트하지 않고 캐치프레이즈와 구성 버튼을 바로 표시한다. 시작 화면의 이미지 미리받기도 같은 경계에서 생략한다. 기존 모바일 자산은 보존한다.
- 형태 참고 자료는 manifest와 제작 안내에 보존한다. 특정 제품의 정밀 CAD나 브랜드 로고를 복제한 장면은 아니다.

완성 이미지와 manifest는 `public/pc-assembly/`에 포함되어 pull 후 렌더 없이 사용할 수 있다. 원본 Blender 장면과 제작·재렌더 방법은 [PC 장면 제작 안내](../art/pc-assembly/README.md), 상세 검토 기록은 [장면 규격](../art/pc-assembly/scene-spec.json)에 있다. 480단계라는 수는 모든 기기에서 고정 60fps를 보장하지 않는다.

## 실행·검증

Node.js 24.x와 npm을 준비한 뒤 `frontend/`에서 실행한다.

```powershell
npm.cmd ci
npm.cmd run dev
```

개발 서버 주소는 `http://127.0.0.1:5173`이다. 로그인·저장 등 서버 기능에는 별도 백엔드 실행과 개인 설정이 필요하다. 개인 OAuth 키와 DB 데이터는 pull로 공유되지 않는다. 상품가 준비는 [국내 신품 상품가 안내](../docs/catalog-current-prices.md)를 참고한다.

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
```

2026-10-09 기준 프론트엔드 테스트 106개, ESLint, TypeScript·Vite 빌드를 통과했다. 실제 브라우저에서 일반 데스크톱과 2560×1440 화면의 급격한 왕복 스크롤을 확인했다. 기준·근처 포즈의 표시 해상도가 같고, 큰 화면의 저장된 bitmap 합계는 330,240,000 bytes로 예산 안에 있었다. 첫 화면 공백과 두 번째 조립 구간을 유지했고 하단 부품 이미지 영역이 표시되지 않는 것도 확인했다. 고정 FPS·실제 모니터 간 이동·외부 네트워크 시험은 하지 않았다.

모바일 전용 최적화·검증은 작업 범위에서 제외했다. 최초 로딩 중에는 기준 포즈 준비 상태와 네트워크에 따라 잠깐 기다릴 수 있다. 1600×1200보다 큰 실제 이미지 표시 영역에서는 원본 해상도 자체의 한계가 있다. 이번 화면 변경에서는 백엔드·DB를 수정하지 않았으며 실제 MySQL·OAuth 로그인 통합 시험도 새로 실행하지 않았다.

2026-11-02 PR #45 검토에서는 위 기존 검증에 더해 프론트엔드 테스트 252개·린트·빌드를 통과했다. 320/375/640px 시작 화면의 이미지 미리받기 생략, 641px 이상 미리받기 유지, 모바일 랜딩의 조립 컴포넌트 제외, 모션 감소 정지 화면과 명시적 애니메이션 선택을 자동 테스트했다. 브라우저에서는 데스크톱 키보드 접근의 문구 겹침 수정, 1440px 화이트 모드와 새로고침 후 테마 유지, 375px 모바일 화면을 확인했다. 실제 OS의 모션 감소 설정과 MySQL·OAuth·Windows 수집기 통합은 새로 검증하지 않았다. 기존 500kB 초과 번들 경고는 남아 있다.

2026-11-02 PR #47 검토에서도 테스트 252개·린트·빌드를 통과했다. 실제 브라우저의 320~1920px 화면에서 구성·플랜 배치와 가로 넘침을 확인했다. 1200px에서 입력칸이 사이드바 뒤로 가려지는 문제, 모바일 버튼 넘침, 좁은 플랜의 예산 입력 배치, 메뉴 선택 점과 계정 안내 줄바꿈을 보완했다. 읽기 전용 가짜 API 응답과 밝음·어두움 CSS 조건을 고정한 별도 검증 서버로 PC 수정·상세·목록을 확인했으며, 검색 모달의 Escape·초점 복귀와 480px 패널, 이름·부품 수량·개당 용량·미완성 검색어의 뒤로가기·새로고침 복원도 확인했다. 실제 OS 테마 변경·MySQL 저장·OAuth·Windows 수집기 통합은 실행하지 않았다. 기존 번들 크기 경고는 남아 있다.
